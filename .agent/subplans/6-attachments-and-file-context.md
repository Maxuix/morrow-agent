## 目标

支持文件选择/拖放、图片粘贴和 @ 工作区文件。基础支持文本/源码、图片、PDF，并验证实际
模型输入、历史恢复及产物保留关系，消除“上传成功但模型未收到内容”的假交互。

## 修改归属

- core 消息/附件引用、能力与快照合同。
- application 附件生命周期、文件引用/上下文投影、预算与内容解析。
- adapters 的 Artifact/blob、Operational Store 迁移及模型序列化。
- server 附件/文件搜索/预览/内容读取与受控上传接口。
- GUI AttachmentComposer/Tray/Preview、拖放/粘贴/@、错误与模型兼容提示。
- tests：附件输入、恶意/超限内容、快照、fork、cleanup、backup、Provider/GUI 测试。

## 存储、解析和显示约束

- 上传不写入用户项目目录；读取工作区文件和上传外部文件是不同来源。
- Log 仍由原 writer 追加；不引入第二套 Chat 存储或直接复制会话内容。
- 二进制内容不进入 YAML、ApplicationEvent 或命令回执；消息/快照保留受控引用。
- 字节数、文件数、像素/页数、解析耗时、上下文 token/字符占用分别受真实配置限制，
  Core 下发实际限制，不能静默截断。
- 文本/PDF/图像内容视为用户输入资料，不成为工具权限、系统提示或工作区授权。
- HTML/SVG/远程资源不执行或自动加载；预览遵守 CSP 和类型校验。
- 不支持 Office/音视频解码；显示真实可处理类型，不声称任何附件都已读入。
- 新解析/图像依赖须先形成具体选型并获得授权；独立的引用/状态/文本工作可继续推进。
- 解析工作不能占用 mutation bus 或延长数据库事务跨 await。

## 验证用例

| 场景 | 必须断言 |
|---|---|
| 代码文件/@ 文件 | 模型收到预期文本/来源，历史绑定提交时版本 |
| 图片/仅附件消息 | Provider 接收真实图像结构，空正文条件全链路一致 |
| 文字/扫描/混合 PDF | 提取路径和页覆盖真实，缺失/超限明确可见 |
| 伪扩展名/损坏/过大内容 | 后端拒绝且保持草稿可修复，原始异常不泄露 |
| 模型不兼容/运行中排队 | 不丢内容、不换模型，提交绑定原设置与附件 |
| 重复上传/发送失败重试 | 引用和实际模型请求不重复，不产生无限 orphan |
| Session/Workspace 交叉 ID | 无法读取别处附件；目录/符号链接边界一致 |
| fork/backup/cleanup/迁移 | 可恢复引用完整，未引用草稿可清理，旧文本可读 |
