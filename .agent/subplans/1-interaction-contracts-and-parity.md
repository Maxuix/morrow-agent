## 目标

把已确认产品方案转成可实现、可验证的交互与数据合同，消除重复提交、跨工作区串状态、
附件和思考参数仅有 UI 等风险。交付合同与完整功能映射，不在本子计划提前开发运行时或界面。

## 必须写清的边界

| 边界 | 合同必须回答 |
|---|---|
| 提交确认 | HTTP 回执代表排队、已接纳还是 Log 已写入；客户端如何核对 |
| 重试/重复 | 客户端 ID 如何贯穿首次提交、steering、follow-up、Turn 和模型驱动 |
| 状态来源 | 每个 timeline 类型由哪个既有权威对象投影，谁能写入 |
| 运行隔离 | API handler、队列、Core loop、SQLite 和 driver 的生命周期与 await 边界 |
| 历史与流 | 刷新和 Core 重启能恢复哪些事实，未提交尾部如何诚实展示 |
| 设置/附件 | 校验、冻结、摘要、持久化、恢复与预算在哪个 owner 完成 |
| 维护 | backup/cleanup/relink/归档遇到活动运行时如何处理 |
| 兼容 | 旧客户端/纯文本消息/快照/旧工作区如何读、升级与恢复 |
