# 阶段 4：会话、上下文与记忆

> 状态：未开始  
> 阶段结果：一个可以恢复历史会话，并跨会话保留必要信息的个人 Agent  
> 上级文档：[开发路线总览](../ROADMAP.md)  
> 上一阶段：[阶段 3：本地工具与安全](stage-3-local-tools-and-safety.md)  
> 下一阶段：[阶段 5：Skills 与扩展生态](stage-5-skills-and-extensions.md)

## 一、阶段目标

让 Morrow 从一次性进程变成可以长期使用的个人 Agent：能够恢复历史会话、管理长上下文，并以透明、可控的方式保留跨会话信息。

阶段 1 曾用 Handoff 摘要验证轻量连续性；该过渡特性已在阶段 2 后移除。当前起点是持久化的
工作空间身份/Profile/Preferences 与进程内 ConversationLog；本阶段才建设完整会话与长期记忆能力。

## 二、进入条件

- 本地工具调用已经稳定，真实任务不会轻易破坏工作空间。
- 工作空间身份、Profile 和 Preferences 具有清晰的权威来源。
- Agent Loop 的消息与工具记录格式已经稳定。

## 三、计划范围

- 持久保存用户、助手和工具消息。
- 创建、列出、恢复、归档和删除会话。
- 会话始终绑定明确的工作空间和配置快照。
- 为长对话建立上下文预算、裁剪和压缩机制。
- 保留关键决定、未完成事项和工具执行结果的必要信息。
- 区分用户偏好、项目知识、Agent 经验和临时状态。
- 记忆必须能够查看来源、修改、删除和禁用。
- 默认防止不同工作空间的项目记忆相互污染。
- 处理配置和状态格式升级、备份与恢复。
- 明确唯一权威数据源，避免多种存储互相同步失控。

## 四、暂不包含

- 不透明、不可审查的无限自动记忆。
- 默认把完整聊天记录发送给第三方记忆服务。
- 多设备实时同步和团队共享记忆。
- 为追求“智能”而提前引入复杂向量基础设施。
- 定时任务、后台任务和子 Agent。

## 五、阶段交付物

- 规范化的会话存储与消息模型。
- 会话创建、恢复、归档和删除入口。
- 上下文预算与压缩策略。
- 可控的长期记忆模型及管理入口。
- 新 Session 数据的备份、恢复和 Schema 迁移方案。
- 数据备份、恢复和 Schema 迁移测试。

## 六、阶段完成标准

- 程序重启后可以继续指定历史会话。
- 恢复后的消息、工具调用和工作空间归属保持一致。
- 长对话达到预算时能够压缩或裁剪，而不是直接失败。
- Agent 能跨会话使用一条经过用户认可的项目知识或个人偏好。
- 用户可以查看该信息的来源并修改或删除它。
- A 工作空间的项目记忆不会默认出现在 B 工作空间。
- 存储损坏或迁移失败时不会静默覆盖原始数据。

## 七、进入阶段时再确认

- 会话的权威存储技术和数据库 Schema。
- 上下文压缩触发条件与摘要格式。
- 长期记忆的数据分类、写入权限和检索策略。
- 是否需要语义检索，以及何时才值得引入 Embedding。
- 数据保留、归档、导出和删除策略。
- 是否以及如何处理旧版遗留 Handoff 数据；任何导入或删除都需要单独的产品与数据决策，
  本路线不作迁移承诺。

阶段 4 完成后，Morrow 才具备长期日常使用所需的连续性基础。
