# 阶段 6：自动化与复杂任务

> 状态：未开始  
> 阶段结果：Agent 可以可靠地执行定时、后台和可分解的长任务  
> 上级文档：[开发路线总览](../ROADMAP.md)  
> 上一阶段：[阶段 5：Skills 与扩展生态](stage-5-skills-and-extensions.md)  
> 下一阶段：[阶段 7：体验、入口与产品化](stage-7-experience-and-channels.md)  

## 一、阶段目标

让 Morrow 从“用户发起一次、完成一次”的助手，进化为能持续跟进任务的个人 Agent，同时保持可观察、可暂停、可取消和可追责。

## 二、进入条件

- 会话、任务状态和恢复机制已经可靠。
- 工具权限、审批、超时和审计机制已经稳定。
- Skills 与 MCP 能以统一能力接口参与任务。

## 三、计划范围

### 定时与后台任务

- 支持一次性任务和周期性任务。
- 持久化任务定义、下次运行时间和最近结果。
- 后台任务可查看、暂停、恢复、取消和手动重试。
- 进程重启后能恢复未完成或待执行任务。

### 长任务可靠性

- 明确任务状态机和检查点。
- 支持超时、失败重试、幂等与中断恢复。
- 为时间、调用次数、模型成本和工具并发设置预算。
- 在需要用户判断时暂停，并保留完整上下文等待继续。

### 任务分解与子 Agent

- 主 Agent 可以把边界清晰的子任务委派给子 Agent。
- 限制并发数、递归深度、预算和可用工具。
- 子任务继承必要上下文，但不默认获得全部个人状态。
- 主 Agent 汇总结果并负责最终一致性。

### 通知与审计

- 对开始、暂停、失败和完成提供统一事件。
- 通知渠道与任务执行逻辑解耦。
- 保存关键决策、外部操作、审批和最终产物记录。

## 四、暂不包含

- 分布式任务集群。
- 面向多租户的 SaaS 调度平台。
- 无预算、无边界的自主循环。
- 不受限制的子 Agent 递归扩张。
- 未经授权代表用户执行高风险外部操作。

## 五、阶段交付物

- 持久化任务模型与调度器。
- 后台 Worker、恢复机制和状态查询接口。
- 预算、重试、取消和人工介入机制。
- 最小子 Agent 委派与结果汇总能力。
- 统一任务事件、通知接口与审计记录。

## 六、阶段完成标准

1. 用户能创建、查看、暂停、恢复和删除一个周期任务。
2. Agent 重启后不会丢失计划任务和进行中任务状态。
3. 长任务可被取消，并清楚报告已经发生的副作用。
4. 达到预算或需要高风险授权时，任务会可靠暂停。
5. 主 Agent 能并行委派有限子任务并汇总可追溯结果。
6. 失败任务可诊断、可重试，且不会产生无界重复执行。

## 七、进入阶段时再确认

- 调度器与 Worker 的进程模型。
- 任务状态机、检查点粒度与幂等约定。
- 通知事件协议及首个通知渠道。
- 子 Agent 的上下文、权限与预算继承规则。
- 高风险后台操作的审批有效期。
