# 阶段 7：体验、入口与产品化

> 状态：未开始  
> 阶段结果：形成可长期日用、可安装维护的个人 Agent 1.0  
> 时间参考：根据真实使用反馈持续迭代  
> 上级文档：[开发路线总览](../ROADMAP.md)  
> 上一阶段：[阶段 6：自动化与复杂任务](stage-6-automation-and-complex-tasks.md)  

## 一、阶段目标

基于前六个阶段的真实使用反馈，选择一个最有价值的交互入口做深，并完成安装、升级、诊断和数据管理，让 Morrow 从工程原型成为可长期使用的个人产品。

## 二、进入条件

- 核心能力已经稳定，并经过真实项目使用。
- 已经知道用户最常见的任务、入口和中断点。
- 会话、工具、扩展和自动化共享同一套核心接口。

## 三、计划范围

### 选择并做深首个入口

- 根据真实使用证据，在 TUI、Web、桌面端或消息渠道中选择一个。
- 客户端只负责交互，不复制 Agent 核心逻辑。
- 支持任务状态、流式反馈、审批、取消和恢复。
- 保留 CLI 作为稳定的开发、诊断和自动化入口。

### 初次使用体验

- 简化安装、登录模型服务和首次工作空间建立。
- 用对话完成个性化初始化，避免要求用户手改大量配置。
- 清楚解释数据位置、权限范围和可撤销操作。
- 为缺少凭据、网络异常和能力不可用提供可执行提示。

### 产品维护能力

- 提供版本升级、配置迁移和状态 schema 迁移。
- 提供 `doctor`、日志导出和问题诊断。
- 支持个人数据备份、恢复和彻底删除。
- 建立崩溃恢复、性能基线和兼容性测试。

### 日用体验

- 统一通知、任务进度与跨入口交接。
- 优化键盘操作、可访问性和错误反馈。
- 基于使用反馈收敛默认值，减少配置负担。
- 形成稳定发布节奏和回归测试清单。

## 四、暂不包含

- 同时实现所有客户端和消息渠道。
- 在每个客户端复制一套业务与状态逻辑。
- 为展示效果引入尚未验证的新核心能力。
- 在个人产品边界未验证前转向多用户 SaaS。
- 隐藏自动化副作用或数据保存位置。

## 五、阶段交付物

- 一个完成度高的首选交互入口。
- 可复现的安装、升级与卸载流程。
- 对话式首次配置和工作空间初始化。
- 诊断、日志、备份、恢复与迁移工具。
- 个人 Agent 1.0 的发布标准和维护手册。

## 六、阶段完成标准

1. 新用户能在短流程内完成安装、模型授权和第一次对话。
2. 常用任务无需编辑配置文件即可完成个性化设置。
3. CLI 与首选客户端看到一致的任务和工作空间状态。
4. 升级失败可诊断，已有个人状态不会静默损坏。
5. 用户能查看、备份、恢复和删除自己的全部数据。
6. Morrow 能作为真实项目中的日常主入口持续使用。

## 七、进入阶段时再确认

- 首选交互入口及其选择证据。
- 客户端与核心进程的通信方式。
- 安装包、自动更新与版本支持策略。
- 数据备份格式和跨设备迁移边界。
- 1.0 的稳定性、性能与隐私指标。
