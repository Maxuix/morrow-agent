# 阶段 3：本地工具与安全

> 状态：进行中（已完成：通用工具策略、终端审批与配置工具先行切片）

## 一、阶段目标

围绕独立开发者最常见的本地工作，为 Agent 增加文件、搜索、编辑和终端能力，同时建立明确的工作空间与权限边界。

本阶段追求的是少量真实工具的安全闭环，不是一次性加入所有开发工具。

## 当前先行切片

阶段 3 先以通用本地工具策略、审批端口和第一个状态化工具垂直切片建立安全基础。
当前先行切片已实现 Registry/Executor 的通用风险与审批元数据、失败闭环、完整工具 Schema、
终端审批适配器，以及通过 `ConfigPatchService` 接入生产的 `update_configuration` 状态化工具；
文件读取、搜索、编辑、Shell、Git 和其他本地工具仍未开始。
本阶段的本地工具 MVP 需要另行明确范围并获得显式授权；完成本先行切片不代表阶段 3 完成。

## 二、进入条件

- 阶段 2 的 Agent Loop、停止条件和错误处理已经通过验收。
- 工具接口可以表达参数校验、执行结果和风险等级。
- 工作空间身份和隔离规则已经稳定。

## 三、计划范围

- 读取指定工作空间内的文本文件。
- 按文件名或文本内容搜索项目。
- 创建、修改和补丁更新文件。
- 展示修改前后的差异。
- 在受控工作目录中执行终端命令。
- 支持运行项目已有的测试或校验命令。
- 限制路径穿越、符号链接逃逸和工作空间外访问。
- 对命令设置超时、输出限制和可取消机制。
- 按风险区分自动允许、需要确认和默认拒绝的操作。
- 删除、覆盖、外部发送及其他高风险行为必须明确确认。
- 保留足够的操作记录，让用户知道 Agent 做过什么。

## 四、暂不包含

- 默认访问工作空间外的任意个人文件。
- 无确认删除、覆盖或执行明显危险命令。
- 自动 Git 推送、合并、发布或部署。
- 浏览器控制、云端机器和远程执行环境。
- MCP、长期记忆、后台任务和子 Agent。

## 五、阶段交付物

- 文件读取与项目搜索工具。
- 安全的文件修改与差异展示工具。
- 受控终端执行工具。
- 统一的路径安全和风险判定层。
- 权限确认与拒绝流程。
- 使用临时仓库执行的端到端测试套件。

## 六、工具分层与实现约束

阶段 3 的所有新工具必须遵守架构基线中的统一工具能力边界：

- `AgentLoop`、`ToolExecutor` 和 `SessionOrchestrator` 不得按工具名称实现文件、Shell、Git 或其他领域分支。
- `RegisteredTool` handler 只负责把已校验的标准参数映射到受限能力，并把领域结果返回统一工具结果。
- 文件、Shell、Git 等能力必须通过显式注入的 Service/Port 访问工作空间与操作系统，不得由 handler 直接
  绕过路径、权限、预算或审计边界。
- 路径解析、工作空间约束、风险等级、审批、超时、取消、输出限制和操作记录应由可复用的通用策略层
  统一处理，不能在每个工具中各自实现一套。
- 纯函数或只读取构造时注入不可变数据的工具无需为了形式统一而创建空 Service；解耦要求约束的是依赖
  方向和数据所有权，而不是文件或类的数量。
- 新增工具应只需要注册新的标准 ToolDefinition、参数模型和 handler，不应修改普通 Agent Loop 的状态机。

同一领域能力如果同时由 Slash Command、自然语言 Tool 或未来入口使用，必须共享同一个 Application
Service。Provider 只接收标准工具 wire；风险、审批和本地执行元数据只存在于本地 Registry/Executor。

## 七、阶段完成标准

- Agent 可以在测试项目中定位问题、修改文件并运行验证命令。
- 默认无法读取或修改当前工作空间之外的路径。
- 路径穿越和符号链接逃逸会被阻止。
- 高风险操作不会在没有明确确认时执行。
- 命令超时、中断和超量输出不会卡死 Agent Loop。
- 用户能够查看实际修改和执行记录。

## 八、进入阶段时再确认

- 第一批本地工具的精确清单。
- 文件修改采用整文件写入、补丁还是两者并存。
- 风险等级、审批模式和命令允许规则。
- 是否在本阶段加入只读 Git 信息与本地提交能力。
- 操作日志、恢复和撤销需要达到什么程度。

阶段 3 完成后，Morrow 才形成可用于真实本地开发任务的 MVP。
