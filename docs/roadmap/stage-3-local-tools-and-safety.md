# 阶段 3：本地工具与安全

> 状态：未开始  
> 阶段结果：一个可以在指定工作空间中安全完成真实开发任务的 Agent  
> 累计时间参考：5–8 个有效开发日（达到本地工具 MVP）  
> 上级文档：[开发路线总览](../ROADMAP.md)  
> 上一阶段：[阶段 2：Agent 核心能力](stage-2-agent-core.md)  
> 下一阶段：[阶段 4：会话、上下文与记忆](stage-4-sessions-context-and-memory.md)

## 一、阶段目标

围绕独立开发者最常见的本地工作，为 Agent 增加文件、搜索、编辑和终端能力，同时建立明确的工作空间与权限边界。

本阶段追求的是少量真实工具的安全闭环，不是一次性加入所有开发工具。

## 二、进入条件

- 阶段 2 的 Agent Loop、停止条件和错误处理已经通过验收。
- 工具接口可以表达参数校验、执行结果和风险等级。
- 工作空间身份和隔离规则已经稳定。

## 三、计划范围

- 读取指定工作空间内的文本文件。
- 按文件名或文本内容搜索项目。
- 创建、修改和补丁更新文件。
- 展示修改前后的差异。
- 在受控工作目录中执行终端命令。
- 支持运行项目已有的测试或校验命令。
- 限制路径穿越、符号链接逃逸和工作空间外访问。
- 对命令设置超时、输出限制和可取消机制。
- 按风险区分自动允许、需要确认和默认拒绝的操作。
- 删除、覆盖、外部发送及其他高风险行为必须明确确认。
- 保留足够的操作记录，让用户知道 Agent 做过什么。

## 四、暂不包含

- 默认访问工作空间外的任意个人文件。
- 无确认删除、覆盖或执行明显危险命令。
- 自动 Git 推送、合并、发布或部署。
- 浏览器控制、云端机器和远程执行环境。
- MCP、长期记忆、后台任务和子 Agent。

## 五、阶段交付物

- 文件读取与项目搜索工具。
- 安全的文件修改与差异展示工具。
- 受控终端执行工具。
- 统一的路径安全和风险判定层。
- 权限确认与拒绝流程。
- 使用临时仓库执行的端到端测试套件。

## 六、阶段完成标准

- Agent 可以在测试项目中定位问题、修改文件并运行验证命令。
- 默认无法读取或修改当前工作空间之外的路径。
- 路径穿越和符号链接逃逸会被阻止。
- 高风险操作不会在没有明确确认时执行。
- 命令超时、中断和超量输出不会卡死 Agent Loop。
- 用户能够查看实际修改和执行记录。

## 七、进入阶段时再确认

- 第一批本地工具的精确清单。
- 文件修改采用整文件写入、补丁还是两者并存。
- 风险等级、审批模式和命令允许规则。
- 是否在本阶段加入只读 Git 信息与本地提交能力。
- 操作日志、恢复和撤销需要达到什么程度。

阶段 3 完成后，Morrow 才形成可用于真实本地开发任务的 MVP。
