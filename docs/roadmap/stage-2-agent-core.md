# 阶段 2：Agent 核心能力

> 状态：未开始  
> 阶段结果：一个可以自主执行若干步骤、完成简单任务的 Agent  
> 上级文档：[开发路线总览](../ROADMAP.md)  
> 上一阶段：[阶段 1：方向确定与可运行原型](stage-1-direction-and-prototype.md)  
> 下一阶段：[阶段 3：本地工具与安全](stage-3-local-tools-and-safety.md)

## 一、阶段目标

在连续对话之上加入最小工具调用循环，让模型能够选择工具、读取结果并继续推理，直到完成任务或触发停止条件。

这一阶段的核心是把“聊天程序”变成“能够采取受控行动的 Agent”，但暂不授予它真实的本地文件和终端能力。

## 二、进入条件

- 阶段 1 的终端对话、流式输出和错误处理已经稳定。
- Provider 接口能够承载模型请求与响应扩展。
- 会话中断不会破坏阶段 1 的配置和工作空间状态。

## 三、计划范围

- 定义统一的工具描述、参数 Schema、执行结果和错误格式。
- 建立最小工具注册与发现机制。
- 实现模型调用、工具执行、结果回传和继续推理的循环。
- 使用无本地副作用的演示工具验证循环，例如计算、时间或内存中的结构化数据操作。
- 限制最大步骤数、总运行时间、单次工具超时和输出体积。
- 支持用户中断正在执行的 Agent 循环。
- 区分可重试错误、工具失败、参数错误和不可恢复错误。
- 保持模型消息序列合法，避免无限重试和循环调用。
- 为每次运行提供清晰的步骤状态和最终结果。

## 四、暂不包含

- 文件读取、搜索、编辑和补丁应用。
- Shell 命令、测试运行和 Git 操作。
- 浏览器、网络搜索和外部系统集成。
- MCP、Skills、插件和多模型路由。
- 完整会话恢复、长期记忆、定时任务和子 Agent。

## 五、阶段交付物

- 独立于具体 Provider 的 Agent Loop。
- 最小工具协议和工具注册表。
- 一组无危险副作用的演示工具。
- 步骤预算、超时、中断和失败处理机制。
- Agent 运行过程的终端状态展示。
- 覆盖正常完成、参数错误、超时、中断和循环上限的测试。

## 六、阶段完成标准

- Agent 能从一个用户目标出发，自主调用至少两个工具步骤并给出最终答案。
- 每次工具结果都会正确回到模型上下文，不丢失调用关联。
- 达到步骤、时间或输出上限时能够安全停止并说明原因。
- 工具失败不会导致程序崩溃或无上限重试。
- 用户可以中断任务，之后继续正常对话。
- 阶段 1 的配置隔离与交接能力没有被破坏。

## 七、进入阶段时再确认

- 采用哪一种工具 Schema 和 Provider 兼容策略。
- Agent Loop 的状态机与消息格式。
- 默认最大步骤数、超时和重试策略。
- 演示工具的具体集合。
- 工具执行日志需要保存到什么粒度。

阶段 2 通过后，才向 Agent 开放真实的本地项目操作能力。
