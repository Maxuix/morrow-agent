# Morrow 个人 AI Agent 开发路线总览

> 状态：阶段 1 与阶段 2 已完成；阶段 3 尚未开始
> 用途：说明项目整体概念，并维护阶段顺序、当前状态和详细路线入口；具体范围、决策与验收标准以各阶段文档为准。

## 项目概览

Morrow（中文名“承序”）是一个面向个人长期使用的 AI Agent，首先服务于独立开发者的编程与项目推进，随后逐步扩展到办公、信息整理和日常协作。

长期目标是让它以工作空间为边界理解项目并在多次使用之间延续必要信息。当前版本只在单个进程内
保持 ConversationLog；重启恢复属于尚未开始的阶段 4，不是现有能力。

### 主要用途

- 在编程项目中持续协助分析、实现、调试和验证工作。
- 保存工作空间 Profile、Preferences 和 Provider 配置。
- 在同一进程内保持连续对话；未来再支持重启后的会话恢复。
- 根据个人和项目习惯调整语言、表达方式与协作方式。
- 随着能力成熟，处理办公、信息整理、周期任务和其他个人事务。

### 整体能力方向

- **持续对话**：当前围绕工作空间进行进程内协作；阶段 4 才增加可恢复会话。
- **项目连续性**：当前由项目档案和偏好提供静态背景，未来由持久化 Session 与记忆承接工作脉络。
- **任务执行**：逐步获得文件、终端和其他工具能力，完成真实任务，而不只提供建议。
- **自主配置**：用户通过自然语言表达偏好和项目要求，不依赖频繁手改配置文件。
- **能力扩展**：通过 Skills、MCP、模型 Provider 和其他适配器按需增加能力。
- **自动化协作**：未来支持后台任务、周期任务和受约束的任务分解。
- **多种入口**：核心能力成熟后，可按真实需求接入终端、Web、桌面端或消息渠道。

### 项目特点

- **以个人为中心**：优先适配个人长期工作方式，而不是从多用户平台出发设计。
- **以工作空间隔离上下文**：不同项目拥有独立档案和状态，默认不会互相污染。
- **用户拥有数据**：个人配置和项目状态应当可查看、修改、删除、导出与迁移。
- **本地状态优先**：个人上下文默认保存在本地；外部模型服务不等于把所有项目状态托管出去。
- **自然形成个性化**：通过日常对话逐步建立配置，尽量减少传统参数面板带来的负担。
- **安全且可控**：能力越强，权限、审批、执行边界、资源预算和操作记录越明确。
- **核心与扩展解耦**：保持 Agent 核心稳定，把模型、存储、工具、Skills 和交互入口放在可替换的边界之外。
- **分阶段演进**：先完成可运行、可验证的小闭环，再根据真实使用逐步增加能力。

Morrow 的差异化不在于内置最多的工具或支持最多的模型，而在于成为一个了解个人工作方式、能够保持项目连续性、同时仍由用户控制的长期协作者。

## 当前与长期边界

当前持久化工作空间身份、Profile、全局/工作空间 Preferences、Provider 配置和凭据引用。
Session-owned ConversationLog 只存在于当前进程，没有 restart resume、list、archive、delete 或 Fork。

阶段 4 才设计持久化 Sessions、恢复/列表/归档/删除、Fork、上下文摘要或 checkpoint，以及长期记忆。
其存储技术和迁移策略尚未决定；旧版遗留数据不获得隐含导入承诺。
