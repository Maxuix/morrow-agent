## Code review 复核与补修

审阅指出的四类偏差均已复现并修正：

- 压缩失败阶段由抛出点标记。模型请求超限保留 `summary_request/context_overflow`
  及安全的 HTTP 状态类别；响应为空或非 `stop` 标记为
  `summary_parse/invalid_response`；摘要文本解析失败为
  `summary_parse/invalid_summary`；指令校验失败为
  `source_projection/invalid_instructions`。两条自动压缩恢复路径均输出同一结构化失败事件。
- 终态失败原因由 `terminal_error()` 统一输出。答案提交、响应解释以及工具意图的
  计划、准备、提交、可见性失败使用固定短代码，不带异常原文；不确定提交状态仍不自动重试。
- Harbor 继续丢弃原始 stderr，避免上游正文进入 JSONL。headless 流异常结束和终态观察
  不可用时，CLI 向 diagnostics sidecar 输出固定原因码。
- 输入额度不变量移入 `AgentPolicy.resolve()`；driver 和容器 bootstrap 都调用同一策略。
  第二份预留被明确命名为系统提示及工具 schema 开销额度。收集器移除旧的
  `context_compactions` 别名，只保留成功摘要、丢弃周期和清除周期三项独立计数。

以上仅为代码和离线验证，尚未产生新的 89 题正式成绩。
